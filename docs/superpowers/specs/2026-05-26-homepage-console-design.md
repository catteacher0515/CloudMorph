# CloudMorph 首页控制台设计稿

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 设计一个有明确品牌感和控制台气质的首页，让用户在第一屏就能看见应用概览、最近生成记录、工作流状态和快捷入口。

**Architecture:** 首页采用单页控制台结构，不做营销型落地页。整体视觉基调为 `Midnight Control Room`，用深石墨背景、琥珀高亮和半透明玻璃面板构建“AI 生成工坊”的总指挥台感。信息层级按照“全局导航 -> 主视觉 -> 状态概览 -> 业务面板 -> 活动时间线”展开，所有模块都以可点击的卡片形式连接到后续页面。

**Tech Stack:** Vue 3、Vite、原生 CSS、Vue Router 4

---

## 设计目标

- 让用户一眼看懂平台当前状态
- 让首页不仅能看，还能直接操作
- 让视觉语言区别于常见白底 SaaS 仪表盘
- 为后续应用管理、工作流监控、生成历史、部署记录提供统一入口

## 视觉方向

- 深色底：使用石墨黑、炭黑和少量冷灰层次
- 强强调色：琥珀金、橙金色用于按钮、数字、重点标签
- 面板风格：半透明玻璃感卡片，边框有轻微高光
- 视觉气质：专业、克制、带机械控制台感
- 禁止项：不使用紫色渐变白底、不过度依赖默认卡片风、避免普通企业后台模板感

## 页面结构

### 顶部导航

- 左侧放产品名 `CloudMorph`
- 中间放全局搜索框
- 右侧放 `新建应用` 主按钮、通知入口、用户头像

### 主视觉区

- 左侧是大标题和一句产品叙事文案
- 标题语气要像控制台，而不是宣传页
- 下方放两个主动作：
  - `创建应用`
  - `进入工作流`
- 右侧放今日状态摘要卡，展示：
  - 今日生成数
  - 成功率
  - 部署数
  - 待处理任务

### 中部业务区

- 左栏：最近应用列表
  - 应用名称
  - 生成类型
  - 最近更新时间
  - 部署状态
- 中栏：最近生成记录
  - prompt 摘要
  - 当前状态
  - 关联应用
- 右栏：工作流状态面板
  - 素材收集
  - 提示词增强
  - 智能路由
  - 代码生成
  - 项目构建
  - 构建修复

### 底部辅助区

- 左侧：最近活动时间线
- 右侧：快捷入口卡片
  - 应用管理
  - 生成历史
  - 部署记录
  - 工作流监控

## 交互设计

- 页面首次加载时，标题、状态卡、列表卡分层淡入
- 卡片 hover 时，边框、阴影和顶部高光轻微增强
- 主按钮只保留一个最强强调色，避免多个按钮同时抢焦点
- 所有列表项都支持点击跳转到对应详情页
- 失败状态必须可跳转：
  - 构建失败跳转到工作流或修复入口
  - 部署失败跳转到部署详情或应用详情

## 文案原则

- 文案要像真实产品，不像口号
- 每个模块都要告诉用户“下一步可以做什么”
- 空状态要简洁，不说教，不堆叠长句
- 首页主标题要有产品身份感，体现“生成工坊 + 控制台”而不是普通后台

## 响应式策略

- 桌面端采用三栏到四栏布局
- 平板端折叠为两栏
- 移动端按单列堆叠，保留导航、主视觉、状态和关键列表
- 移动端保证主按钮和核心状态始终可见

## 数据来源

首页数据优先来自现有后端接口与实体：

- 应用列表
- 最近生成记录
- 部署状态
- 工作流状态
- 最近活动

如果后端暂时没有完整聚合接口，可以先用前端分开拉取后拼装首页卡片数据。

## 范围边界

本次设计只覆盖首页控制台，不包含：

- 应用详情页
- 工作流详情页
- 登录注册页
- 公共营销页

## 验收标准

- 页面第一眼能分辨出这是 AI 生成平台的控制台，而不是普通管理后台
- 所有核心业务入口在首屏可见
- 视觉风格统一，不能出现多套风格混杂
- 首页不依赖复杂交互也能成立
- 桌面和移动端都能正常展示关键内容
